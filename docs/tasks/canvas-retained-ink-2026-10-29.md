# Saved Canvas ink performance

Owner reports 1.0.6 still has severe lag after drawing, including viewing and
panning; an empty Canvas is smooth. Preserve appearance and features. This
corrects the incomplete earlier hot-path optimization, not a new feature batch.

## Findings and changes

- The old vector entry limit admits only 1024 visible strokes even when the
  200k-sample budget has room. Dense short-stroke boards repeatedly render the
  excess samples. Increase the entry allowance to 8192 with the sample budget
  unchanged; native resources remain bounded and offscreen entries reclaimable.
- Per-stroke image generation repaints saved content repeatedly during warmup.
  The editor now uses small, ordered complete-stroke world layers, retained in
  repaint boundaries at device density. Panning moves existing ink; edits only
  invalidate the affected group. The GPU can cache whole groups without an
  individual image/readback job for every stroke. Groups are bounded by element
  count/sample count, padding fits actual pen coverage, and huge imported bounds
  are cropped safely outside the viewport. Zoom regenerates exact vectors.
- Paper and interaction overlays remain viewport-sized, so gradients, blueprint
  sheet borders, grid, selection, previews and labels are not repeated per group.
  Column-first then insertion order is preserved, including mixed ink/objects.
- Remote awareness has a separate repaint boundary. Live pressure geometry
  parses only appended samples and records stable 128-segment vector prefixes;
  the changing brush exit taper remains in the live tail. The original nib
  renderer is used for every segment. Ruler replacement/new gesture resets the
  cache; no source samples are reduced or persisted differently.

An initial spatial tile prototype was rejected by fidelity tests: cutting round
pressure segments at internal tile edges changed coverage. Complete strokes
avoid those seams. Native baseline 1500 short strokes measured multi-second GPU
frames; therefore CPU-only microbenchmarks were insufficient for this report.

Palette recreation was another major hot path: OrbitColors used identity
equality, so equivalent tokens generated by theme rebuilding/interpolation
invalidated every saved layer. Equality/hash now use all 29 color roles. Tests
check equivalent/copy/interpolated palettes and changes to every individual role.

## Validation

42 focused drawing/layer/focus/live presence tests pass. Long-stroke append,
ruler replacement and restart match the full renderer exactly across all seven
styles. Saved-layer checks match exactly at integer transforms; at 1.25 zoom,
separate layer transforms introduce isolated antialias rounding (max 6/255 in
195 out of 1,920,000 channels), with no missing stroke coverage or internal seams.
No resolution reduction is used. Final acceptance: 80 focused Canvas/live/theme
checks pass; separate pressure endpoint/palm cancellation/undo check passes.
20 export/background/performance/fidelity checks also pass (some overlap).
Analyzer clean (38.9 s); strict format 864 files unchanged. Final Windows build
112.8 s, signed Android 1.0.7+8 build 144.7 s. Both retain registered Google config;
published with complete setup and verified APK:
https://github.com/iax32/Orbit-Note/releases/tag/preview-1.0.7-2026-10-29
Source 4b4529d59a2108cd1875c846387e43d41442d3a0. Setup built in 11.5 s;
APK 139740994 bytes, setup 27311274 bytes. Six remote asset sizes/digests match
local checksums. Original Android package/certificate retained. Windows AOT is
newer than every lib source. No GitHub workflow ran for this source commit.

Final native run at 100 Hz, with concurrent build activity:

| Workload | GPU P95 | UI P95 |
| --- | ---: | ---: |
| Pan, 100k saved pressure samples | 3.494 ms | 5.832 ms |
| Remote cursors, unchanged saved ink | 3.500 ms | 3.337 ms |
| Synthetic stylus, 100k saved samples | 7.496 ms | 3.851 ms |
| 1500 short strokes, retained layers, complete stage | 115.946 ms | 16.403 ms |
| Same retained stage, excluding first 12 frames | 3.928 ms | 16.218 ms |

Legacy dense-board GPU frames reached 7.89 s (bounded six-frame baseline);
retained complete-stage maximum 562.842 ms, one large outlier at frame 75 and
initial cache preparation still visible. Do not hide these with warm-only stats
or claim zero jank. The comparison harness additionally reconstructs a full
ColorScheme per group, so dense UI timings include avoidable harness overhead;
production reads Theme.of(context).colorScheme. Real stylus/Lenovo acceptance
and extreme-board cold-start optimization remain distinct follow-up work.

The native tool uses synthetic documents, injects events only into its own Flutter
binding, and never moves the OS cursor or opens user Vaults. CPU/GPU frame timings
are not hardware stylus latency or proof of physical Lenovo smoothness.
